# Guitar Positions: native apps (iOS, Android, macOS)

Capacitor 8 shells around the same Studio web code that runs on
<https://fretboard.schoensgibl.com>. The plan and its reasoning are in
[`docs/STUDIO_REDESIGN.md`](../docs/STUDIO_REDESIGN.md), section 7. This folder is phase 1:
an offline bundle, the native projects and a local Mac Catalyst build. Plugins, store setup
and CI come later.

| Item | Value |
|---|---|
| Capacitor | 8.5.3 (`@capacitor/core`, `cli`, `ios`, `android`; versions pinned) |
| App ID | `com.schoensgibl.guitarpositions` (TODO: confirm before the first store upload, it cannot change afterwards) |
| iOS | Xcode project in `ios/App`, Swift Package Manager (no CocoaPods), iOS 15+ |
| Android | Gradle project in `android/`, minSdk 24, compile/target SDK 36 |
| macOS | Mac Catalyst build generated by `scripts/build-macos.sh` into `build/` (not committed) |
| Web bundle | `www/`, generated by `scripts/build_app_bundle.py`, not committed |

## How the bundle works

`npm run bundle` runs [`scripts/build_app_bundle.py`](../scripts/build_app_bundle.py). The script:

- copies `static/studio/**` (minus the PWA manifest and tests) into `www/studio/`, and the font
  referenced by `studio.css` into `www/fonts/`;
- writes `www/index.html` from `templates/studio/index.html`. It resolves the Django tags and inlines the
  music catalogue as `<script type="application/json" id="catalog-data">`, the same data
  `/api/catalog/` serves. The app needs no server and works fully offline;
- leaves out the donate link, the "Classic version" link, the service worker, the PWA manifest
  and the website's SEO tags. About and Impressum & Privacy link to
  `https://fretboard.schoensgibl.com/…` with `target="_blank"`. Capacitor opens navigation to
  other hosts in the system browser (Safari / the default Android browser);
- adds a Content-Security-Policy that only allows the bundle itself, so the app makes no
  third-party requests (no tracking, no analytics, no CDNs), and `www/app.css` with
  safe-area padding for the notch, home indicator and Android system bars.

The web Studio templates are not touched. The script fails if the template changed in a way
it no longer understands, instead of shipping a half-converted page.

Catalogue source (it holds music formulas only, no personal data):

| Command | Source |
|---|---|
| `npm run bundle` | `fixtures/studio_music_data.json`, loaded into an in-memory SQLite database and passed through `build_catalog()`. No project database or local settings needed. |
| `PYTHON=… ../scripts/build_app_bundle.py --out www --from-db` | the database configured in the project settings, the same as `manage.py shell` → `build_catalog()`. |
| `… --catalog catalog.json` | a saved JSON export, e.g. `curl -o catalog.json https://fretboard.schoensgibl.com/api/catalog/` |

Use the source that matches production before a store build. If the fixture is older than the
live database, run `--from-db` or `--catalog`.

## Prerequisites

Checked on the development Mac on 2026-10-18:

| Tool | Needed | Found |
|---|---|---|
| Node.js | 22+ (Capacitor 8) | v24.15.0 via nvm (`nvm use 24`) |
| Python | 3.12 with the project requirements (Django) | the repo's `.venv` |
| Xcode | 26+ (App Store uploads need the iOS 26 SDK) | Xcode 26.6, iOS 26.5 simulator runtime |
| Android Studio + SDK | SDK platform 36, build-tools, emulator | `~/Library/Android/sdk`, AVD `Medium_Phone_API_37.0` |
| JDK | 21 | JetBrains Runtime 21 bundled with Android Studio |

On a fresh machine:

1. Node: `brew install node@24` or `nvm install 24`.
2. Python: `python3 -m venv .venv && .venv/bin/pip install -r requirements.txt` in the repo root.
3. Xcode: install from the App Store. Then `sudo xcode-select -s /Applications/Xcode.app/Contents/Developer`,
   `sudo xcodebuild -license accept`, and Xcode → Settings → Components → install an iOS simulator runtime.
4. Android: install Android Studio. In SDK Manager, install "Android SDK Platform 36", "Android SDK
   Build-Tools", "Android SDK Platform-Tools" and "Android Emulator". In Device Manager, create a
   virtual device (any recent Pixel/Medium Phone image). Then add to `~/.zshrc`:

   ```bash
   export ANDROID_HOME="$HOME/Library/Android/sdk"
   export JAVA_HOME="/Applications/Android Studio.app/Contents/jbr/Contents/Home"
   export PATH="$ANDROID_HOME/platform-tools:$ANDROID_HOME/emulator:$PATH"
   ```

## Build and sync

```bash
cd apps
npm install
PYTHON=../.venv/bin/python npm run sync
```

`npm run sync` builds `www/` and runs `npx cap sync`. That copies `www/` into
`ios/App/App/public` and `android/app/src/main/assets/public` (both gitignored) and updates the
native plugin lists. Run it after every change to `static/studio/**`, `templates/studio/index.html`
or the catalogue. Without `PYTHON`, the script runs with `python3` from `PATH`, which must have
Django installed.

## Test the bundle in a browser (offline)

```bash
npm run serve
```

Then open <http://127.0.0.1:8765/>. The page loads only files from `www/`, so it also works with
the network off. Opening `www/index.html` directly via `file://` does not work in Chromium:
browsers block ES module scripts from `file://` URLs. Use the static server.

## Run in the iOS Simulator

```bash
npx cap run ios
```

This command picks a simulator and builds, installs and launches the app. You can also run
`npm run ios`, which syncs and opens `ios/App/App.xcodeproj` in Xcode. There, choose an iPhone
or iPad simulator and press Run (⌘R). The simulator needs no signing team.

Command-line build without signing, e.g. for CI:

```bash
xcodebuild -project ios/App/App.xcodeproj -scheme App -sdk iphonesimulator \
  -destination 'generic/platform=iOS Simulator' CODE_SIGNING_ALLOWED=NO build
```

## Run in the Android emulator

```bash
npx cap run android
```

This command lists running emulators and AVDs, then builds, installs and launches the app. You can
also run `npm run android`, which opens the project in Android Studio. There, pick the emulator
and press Run. Command-line debug APK:

```bash
cd android && ./gradlew assembleDebug
```

The APK lands in `android/app/build/outputs/apk/debug/app-debug.apk`.

## macOS

There are two routes. Neither changes the committed iOS project.

### Local Mac build without an Apple account (Mac Catalyst, ad hoc)

```bash
cd apps
PYTHON=../.venv/bin/python npm run macos
```

The result is `apps/build/macos/Guitar Positions.app`: a universal build (arm64 + x86_64) for
macOS 12+, signed "to run locally" (ad hoc, `CODE_SIGN_IDENTITY=-`). Open it from Finder or with
`open "build/macos/Guitar Positions.app"`. Use `CONFIGURATION=Debug npm run macos` to get a build
you can inspect with Safari's Web Inspector.

[`scripts/build-macos.sh`](scripts/build-macos.sh) builds the bundle and then generates a
throwaway CocoaPods-based copy of the iOS project in `apps/build/macos-catalyst/` (gitignored).
It enables `SUPPORTS_MACCATALYST` there and runs `xcodebuild` for
`generic/platform=macOS,variant=Mac Catalyst`. The committed `ios/` project uses Swift Package
Manager. Its prebuilt `Capacitor.xcframework` only contains iOS device and simulator slices,
so Catalyst can't link against it. CocoaPods compiles Capacitor from `node_modules` instead.
The build needs CocoaPods (`brew install cocoapods`) and a UTF-8 locale; the script sets
`LANG`/`LC_ALL` itself.

An ad hoc build only runs on the Mac that built it, or after the Gatekeeper override on
another Mac. It can't be distributed. Mac App Store or notarised distribution needs a paid
Apple Developer Program team.

### Store route: "Designed for iPad" on Apple silicon (plan 7.2)

Once the iOS app is in App Store Connect, keep "iPhone and iPad Apps on Apple Silicon Macs"
availability on, so Apple-silicon Macs can install the iOS build from the Mac App Store. For a
local test, select the "My Mac (Designed for iPad)" destination in Xcode. That needs a
development team and provisioning profile: Xcode registers this Mac and the App ID with the
team. A free Personal Team can do this, but its profiles expire after 7 days. Registering
`com.schoensgibl.guitarpositions` under a personal team may block that identifier for the
later paid team, so use a separate test ID such as `com.schoensgibl.guitarpositions.dev`.
